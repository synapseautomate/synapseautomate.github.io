# Single-Bet Decision & Non-Goals

## Working default
TradeOps RFQ intake -> quote/checklist draft -> human approval.

This is the current default because the carried-forward plan explicitly names it as the fallback single bet. It is **not yet customer-validated demand** and must change if real inbound/pilot evidence contradicts it.

## Decision dimensions
- access: can the workflow be demonstrated without sensitive data?
- value: does it reduce repeated coordination or preparation work?
- eval: can correct/incorrect routing be tested with clear cases?
- risk: can high-impact actions remain behind human approval?
- pilot ask: can a 14-day controlled pilot be scoped to one workflow?
- moat: does repeated delivery improve templates, exception libraries and evidence?

## Current evidence status
- technical/eval evidence: available from synthetic benchmark packages
- public proof: available
- real customer intent: not measured yet
- paid pilot intent: not measured yet
- revenue: not measured yet

## 90-day non-goals unless real evidence changes the decision
- autonomous quote sending
- autonomous contract acceptance
- autonomous payment/financial commitment
- unlimited custom integrations
- multi-product expansion before one workflow shows demand
- building adjacent features only because they are technically possible

## Stop / change rule
A compliment is not demand. Change the single bet only from measurable evidence such as qualified inbound, willingness to provide redacted data, pilot scope discussion, written next step, accepted proposal or payment.
